# Storage protocol: records on GitHub (direct loading)

Some people keep their records in their own **private GitHub repository** instead of Google Drive. The files are the same documents as in Drive, as plain text. The difference is who reads them: the career-architect server fetches the files a check names, so you send **paths, not text**. A check that needs `skills`, `profile` and three facts files costs a few dozen tokens to call instead of copying tens of kilobytes, and nothing can be mistyped on the way.

Everything in `SKILL.md` still applies. Only the storage protocol changes: use this document instead of `references/storage.md` for a person whose records are on GitHub.

## Which storage a person uses

At the start of a task, call `career_architect__records_status` (no arguments, or `repo` if you already know it).

- `reachable: true`: their records are on GitHub. Note `repo` and `commit`, and follow this document.
- `mode: off`, or `reachable: false` with a `problem` saying no records repository is set up: use Drive (`references/storage.md`).
- `problem` says `repo is required`: ask the person once for their records repository (`owner/name`) unless they already told you, then call it again with `repo`.
- Any other `problem` (sign-in refused, App not installed, not found): tell the person the line it gave and stop. Do not switch to Drive silently.

## Layout

```
<owner>/<repo>                    private, theirs; the Career Architect Records App installed on this repository only
  profile.md                      YAML front matter + notes (identity, never_claim, known_gaps, pending, rr_master)
  rules.md                        standing wording rules
  skills.md                       GENERATED by build_index; never edited by hand
  facts/shared.yaml               aliases, related, credentials, education, log
  facts/<role-id>.yaml            one file per role: its atoms
  jobs/<slug>/jd.md               the posting text, URL and date on the first two lines
  jobs/<slug>/selection.yaml      the resume selection, once written
  jobs/<slug>/cover.yaml          the cover letter, once written
```

The formats are those of `references/storage.md` ("Document formats"), as plain files. No `_history` folder: every save is a Git commit, so every earlier version is in the repository's history. Only `.md`, `.yaml`, `.yml` and `.txt` files are records; the tools refuse anything else.

## Tools

| Tool | For |
|---|---|
| `career_architect__records_status` | which storage, and whether the repository answers |
| `career_architect__records_list` | the files in one folder (`folder: "facts"`, `"jobs/<slug>"`, or empty for the top), each with its `sha` |
| `career_architect__records_read` | read files as text, each with its `sha`, when **you** need the words (writing bullets, showing a line, editing) |
| `career_architect__records_write` | save one whole file, plain text, with the `sha` you read |

## Read: pass paths to the checks

Every check takes a path argument beside each document argument: `skills_path`, `profile_path`, `selection_path`, `cover_path`, `posting_path`, and `facts_paths` (a list) beside `facts_docs`. Use them, and leave the text arguments empty.

- Scoring: `match(skills_path: "skills.md", profile_path: "profile.md", requirements: ...)`.
- Linting and the resume patch: `selection_path: "jobs/<slug>/selection.yaml"`, plus `skills_path`, `profile_path` and `facts_paths: ["facts/shared.yaml", "facts/<role>.yaml", ...]`. Pick role files from the `# Roles` table in `skills.md`, as with Drive.
- Index: `build_index(facts_paths: ["facts/"])`. A path ending in `/` means every file in that folder.
- An edit not saved yet: pass the new text in the text argument and the rest as paths. For facts, text in `facts_docs` and files in `facts_paths` are checked together.

**Pin one task to one version.** Each answer carries `records_commit`. Pass it as `ref` to every later read or check in the same task, so a save in between (by the person, or by you) cannot make two checks see different files. A new task starts without `ref`.

Read a file into the conversation (`records_read`) only when you need its words. The rules on large reads still hold (`references/delegation.md`), but most of the reasons to delegate a check go away: the check no longer needs the text copied into it.

## Write

1. **Validate first,** as with Drive: `build_index` on the complete new set of facts (the changed file as text, the rest as paths) and continue only when `ok` is true; a selection or letter after `lint_resume` / `lint_cover` shows no errors, or saved as `selection.draft.yaml` / `cover.draft.yaml`.
2. **Show the person what changes** (the changed lines), as for any write.
3. **Save the whole file in one call:** `records_write(path, text, sha, message)`. `sha` is the one `records_read` or `records_list` gave you for that file; leave it empty only for a new file. `message` is one line saying what changed; it is kept in the history.
4. **If it is refused because the file changed since you read it,** someone (or another session) saved in between. Read it again, merge, show the person the difference, and save with the new `sha`. Never resend the old `sha` or work around it.
5. **After any facts change,** run `build_index(facts_paths: ["facts/"])` and save its `skills_md` as `skills.md` in the same task. A stale index makes scores wrong.

Tell the person, in one line, what was saved. Every version is kept, so a mistake is undone by saving the earlier text again.

## Rules specific to GitHub

- The repository is the person's own. Never write outside the layout above, never write code, workflows or configuration files, and never ask for or handle a GitHub token: access is through their sign-in or the App, on the server.
- Never move a person between Drive and GitHub without being asked. To move them, read each Drive document (`references/storage.md`, "Read"), run `normalize_text` on it, save it under its path here, then check that `build_index(facts_paths: ["facts/"])` gives the same index as the Drive `skills`. Leave the Drive folder as it is; the person decides when to remove it.
